# DeployStack Satellite

DeployStack Satellite is a MCP (Model Context Protocol) server management service that provides enterprise-ready deployment capabilities for MCP servers. It acts as an intelligent edge worker that bridges centralized management with on-premise MCP server execution.

## Overview

The Satellite service follows the proven GitHub Actions runner pattern for enterprise compatibility, providing:

- **Global Satellites**: Cloud-hosted and operated by DeployStack team
- **Team Satellites**: Customer-deployed within corporate networks
- **HTTP Proxy**: Intelligent routing for MCP server communication
- **Process Management**: Complete lifecycle management for MCP server processes
- **Enterprise Security**: Team isolation, audit logging, and compliance features

## Quick Start

### Development

```bash
# Install dependencies
npm install

# Configure satellite (copy and edit .env file)
cp .env.example .env
# Edit DEPLOYSTACK_REGISTRATION_TOKEN with token from admin

# Start development server
npm run dev

# The server will start on http://localhost:3001
# API Documentation: http://localhost:3001/documentation (comming soon)
# Backend Status: http://localhost:3001/api/status/backend
```

### Production

```bash
# Configure production environment
cp .env.example .env.production
# Configure production values including registration token

# Build the application
npm run build

# Start production server
npm start
```

## Configuration

The satellite service uses environment variables for configuration and automatically manages persistent storage:

### Persistent Storage

Satellites maintain registration state across restarts using local file storage:

```bash
services/satellite/persistent_data/
└── backend.key.json  # API key and registration data
```

**Registration Flow:**

- **First startup**: Uses registration token → Registers → Saves API key to persistent storage
- **Subsequent startups**: Loads saved API key → Verifies with backend → Skips registration
- **Invalid credentials**: Automatically cleared and re-registration attempted

**Benefits:**

- No repeated registration token usage
- Automatic recovery after server restarts
- Seamless development workflow with frequent restarts
- Production resilience for system reboots

### Environment Variables

```bash
# .env file
PORT=3001                           # Server port (default: 3001)
NODE_ENV=development                # Environment mode
LOG_LEVEL=debug                     # Logging level (trace, debug, info, warn, error, fatal)

# Backend Connection (Required)
DEPLOYSTACK_BACKEND_URL=http://localhost:3000  # DeployStack Backend URL

# Backend Polling Configuration (Optional)
DEPLOYSTACK_BACKEND_POLLING_INTERVAL=60         # Command polling interval in seconds (default: 60)

# Satellite Identity (Required)
DEPLOYSTACK_SATELLITE_NAME=dev-satellite-001   # Unique satellite name (10-32 chars, lowercase only)

# Registration Token (Required)
DEPLOYSTACK_REGISTRATION_TOKEN=your_token_here  # JWT registration token from admin

# Status Display Configuration (Optional)
DEPLOYSTACK_STATUS_SHOW_UPTIME=true     # Show uptime in status endpoint (default: true)
DEPLOYSTACK_STATUS_SHOW_VERSION=true    # Show version info in status endpoint (default: true)
```

### Required Environment Variables

**DEPLOYSTACK_SATELLITE_NAME** (Mandatory)

Unique satellite identifier following strict validation rules:

- **Length**: 10-32 characters
- **Characters**: Only lowercase letters (a-z), numbers (0-9), hyphens (-), and underscores (_)
- **No spaces or uppercase letters allowed**
- **Examples**: `dev-satellite-001`, `production_worker_main`, `team-europe-01`

**DEPLOYSTACK_REGISTRATION_TOKEN** (Required for First Startup)

JWT-based registration token for secure satellite pairing:

- **Format**: `deploystack_satellite_global_*` or `deploystack_satellite_team_*`
- **Source**: Generated by administrators via DeployStack Backend API
- **Security**: Single-use tokens consumed during initial registration
- **Usage**: Only required for first startup - subsequent starts use saved API key
- **Scope**: Global tokens serve all teams, team tokens serve specific teams

**How to obtain registration token:**

```bash
# Via Backend API (requires admin authentication)
curl -X POST http://localhost:3000/api/satellites/global/registration-tokens \
  -H "Cookie: your-admin-session" \
  -H "Content-Type: application/json"
```

The satellite will **fail to start** with clear error messages if required variables are invalid or missing. This ensures secure, consistent satellite deployments.

## Development

### Available Scripts

- `npm run dev` - Start development server with hot reload
- `npm run build` - Build for production
- `npm run lint` - Run ESLint with auto-fix
- `npm start` - Start production server

### System Prerequisites

**Local Development:**

- No special requirements - stdio MCP server process management works without isolation
- Plain Node.js spawn() used for easy debugging
- Works on macOS, Windows, and Linux

**Production (Docker):**

- nsjail automatically installed in Docker image for secure process isolation
- See Dockerfile for configuration details

### Initial Setup Requirements

1. **Backend Running**: Ensure DeployStack Backend is running at `DEPLOYSTACK_BACKEND_URL`
2. **Registration Token**: Obtain valid registration token from admin
3. **Environment Configuration**: Configure all required environment variables
4. **Network Access**: Satellite requires outbound HTTPS access to Backend

## Architecture

The satellite service implements a secure three-tier architecture:

1. **MCP Client Layer** - VS Code, Claude, etc.
2. **Satellite Layer** - Edge processing with HTTP proxy + process management
3. **Backend Layer** - Central management and orchestration

### Security Model

- **JWT-Based Pairing**: Secure registration token system prevents unauthorized satellites
- **Admin-Controlled**: Only administrators can generate registration tokens
- **Single-Use Tokens**: Registration tokens consumed after successful pairing
- **Permanent API Keys**: Long-term authentication after initial pairing
- **Team Isolation**: Process-level isolation for multi-tenant deployments

For detailed architecture and security information, see the [Satellite Development Documentation](https://docs.deploystack.io/development/satellite).
